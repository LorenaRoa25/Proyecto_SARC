P021 [Heading 1] 8. Persistencia Firebase
P022 [Normal] El proyecto usa Firebase Authentication para usuarios y Cloud Firestore para datos. Las colecciones globales son usuarios, cursos, recomendaciones y tareasAsistente. Cada documento de datos incluye userId, lo que permite separar multiples usuarios sin crear una coleccion distinta para cada uno.
P023 [Heading 1] 9. Detalle tecnico que conviene sustentar
P024 [Normal] La documentacion tecnica no debe quedarse solo en el listado de archivos. Para defender el proyecto, tambien es importante explicar como circulan los datos entre las vistas, el estado global y Firebase.
P025 [Heading 2] 9.1 Flujo interno del estado
P026 [List Bullet] Las vistas no consultan directamente Firestore; leen y modifican state.db, definido en shared/js/data.js.
P027 [List Bullet] Cuando una accion cambia datos importantes, como una inscripcion o una tarea del asistente, se llama saveDatabase().
P028 [List Bullet] saveDatabase() obtiene el usuario autenticado y delega la escritura a saveUserData() en firebase-service.js.
P029 [List Bullet] firebase-service.js guarda usuario, cursos, recomendaciones y tareas en colecciones separadas, todas asociadas a userId.
P030 [Heading 2] 9.2 Enrutamiento y vistas
P031 [Normal] La navegacion se basa en el hash de la URL. navigation.js cambia window.location.hash y app.js escucha el evento hashchange para decidir que vista renderizar. Si la ruta empieza por detalle/, app.js separa el identificador del curso y lo guarda en state.currentDetailId.
P032 [Heading 2] 9.3 Plantillas HTML
P033 [Normal] Cada vista carga su plantilla HTML mediante loadTemplate(). Luego interpolate() reemplaza marcadores como {{courseList}} o {{name}} por datos reales. Despues de insertar el HTML en el DOM, la vista registra eventos con addEventListener().
P034 [Heading 2] 9.4 Firebase y Firestore
P035 [Normal] Firebase Authentication administra credenciales y sesiones. Firestore guarda los datos academicos del usuario. El proyecto no guarda contrasenas en Firestore. Las reglas de seguridad comparan request.auth.uid con userId para evitar acceso cruzado entre usuarios.
P036 [Heading 2] 9.5 Aspectos a mejorar
P037 [List Bullet] Separar formalmente registro e inicio de sesion; loginWithEmail crea el usuario si no existe, lo cual es util para demo.
P038 [List Bullet] No reiniciar siempre la sesion al cargar si se desea comportamiento productivo persistente.
P039 [List Bullet] Subir avatares a Firebase Storage en vez de guardar imagenes como data URL dentro del perfil.
P040 [List Bullet] Agregar pruebas funcionales para login, filtros, inscripcion, progreso, perfil y reglas de Firestore.
